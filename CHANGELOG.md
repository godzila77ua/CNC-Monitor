# Зміни
## [0.9.7.3] - 2026-05-04

### Додано
- Додано єдину rules-архітектуру для NCStudio та Engrave адаптерів (markers + messages)
- Додано централізовану систему форматування повідомлень через message_rules
- Додано уніфіковану обробку подій START / STOP / PAUSE / RESUME / RAW_INFO
- Додано підтримку fallback-подій для некласифікованих рядків логів (RAW_INFO)
- Додано парсер координат зміни нульової точки з виділенням [G54] та осей

### Змінено
Перероблено логіку детекції подій: сирий рядок лог-файлу тепер використовується для розпізнавання без попередньої модифікації
Розділено етапи обробки:
raw log → detection
cleaned text → output formatting
Уніфіковано підхід NCStudio та Engrave адаптерів до однакової моделі подій
Перероблено STOP-логіку (SIMULATION_STOP vs STOP)
Покращено стабільність таймерів start_time / pause / missing
Виправлено проблему відсутності message_rules у EngraveAdapter (runtime crash)
### Виправлено
Виправлено критичну помилку:
EngraveAdapter object has no attribute message_rules
Виправлено дублювання повідомлень у OFFSET / RAW подіях
Виправлено некоректне форматування CPU_FREQ (CP1251/GBK артефакти)
Виправлено розрив логіки STOP/PAUSE при втраті файлу
Виправлено некоректне формування RESUME після PAUSE
Виправлено проблему з “кракозябрами” у NCStudio логах
### Логіка роботи з NCStudio
Реалізовано стабільну обробку логів NCSTUDIO.LOG
Події визначаються виключно з raw рядка без попередньої очистки
Додано коректну обробку:
запуску обробки
активного виконання
автоматичної зупинки
ручної зупинки
симуляції
Всі повідомлення проходять через rules-based систему форматування
### Логіка роботи з Engrave
Реалізовано файловий watchdog (без лог-файлу)
Додано детекцію:
START (зміна або поява файлу)
PAUSE (таймаут без змін)
RESUME (повернення змін)
STOP (зникнення файлу)
Синхронізовано структуру подій з NCStudioAdapter
### Відомі обмеження
PAUSE визначається евристично (через timeout відсутності змін файлу)
NCStudio залежить від якості лог-файлу (CP1251/GBK декодування)
Деякі CNC повідомлення можуть містити “биті символи” через кодування контролера
Примітки
Це стабілізаційний реліз після великого рефакторингу адаптерів
Архітектура приведена до єдиного стандарту “rules-driven adapters”
Версія вважається production-ready для тестових ПК
Підготовка бази під масштабування (додавання нових станків без зміни core логіки)

## [0.9.7] - 2026-05-03

### Додано
- Додано шаблон конфігурації `config.example.py`
- Стандартизовано структуру конфігурації проєкту для безпечного розгортання
- Уніфіковано логіку обробки подій для подальшого розширення системи

### Змінено
- Покращено структуру CNC Monitor та розділення компонентів
- Винесено конфігурацію з секретами за межі коду (підвищено безпеку)
- Оптимізовано систему сповіщень (консоль + Telegram)

### Логіка роботи з NCStudio
- Реалізовано обробку всіх основних подій зі `NCSTUDIO.LOG`
- Система коректно визначає запуск, активність, а також автоматичне та ручне завершення роботи станка
- Реалізовано систему сповіщень на основі змін у лог-файлі з виводом у консоль та Telegram
- Сповіщення маркуються кольоровими емоджі для швидкого візуального сприйняття

### Відомі обмеження
- Подія "PAUSE" не фіксується у `NCSTUDIO.LOG`, тому постановка на паузу та зняття з неї не визначається системою
- Через це пауза не може бути детектована напряму і потребує альтернативного підходу (таймаут або аналіз поведінки станка)

### Примітки
- Реліз орієнтований на стабілізацію перед версією 1.0.0
- Архітектура підготовлена до розширення підтримки інших станків
